# Gentle — a calculus workspace

A responsive, static web application for finite-dimensional gentle algebras. Draw a quiver, choose vertex and arrow labels, click consecutive arrows to impose quadratic zero relations, and compute with exact coefficients.

Based on Chaparro, Schroll, Solotar and Suárez-Álvarez, [*The Hochschild (co)homology of gentle algebras*, J. Algebra 708 (2026) 138–231](https://doi.org/10.1016/j.jalgebra.2026.04.058) (CSSS26; earlier version arXiv:2311.08003). The correspondence of locators between the two versions is recorded in [docs/csss26/CONCORDANCE.md](docs/csss26/CONCORDANCE.md).

Derived equivalence uses Amiot, Plamondon and Schroll, [*A complete derived invariant for gentle algebras via winding numbers and Arf invariants*, Selecta Math. (N.S.) 29 (2023), Paper No. 30](https://doi.org/10.1007/s00029-022-00822-x), Theorem 7.4.

## Run

```sh
npm start
```

Open **http://localhost:5173**. This uses Python 3's static HTTP server. The application has no npm dependencies, backend or database. Alternatively, run `npm run cards` and `npm run docs`, then serve this directory with any static HTTP server. The generated `methods.html` and `about.html` pages use the app stylesheet and theme chooser; they are ignored at the repository root. ES modules and workers require HTTP(S), rather than opening `index.html` as a `file://` URL.

## Deploy

```sh
npm run build
```

`tools/deploy.sh` builds and copies `dist/` with `rsync --delete` to `gjasso@mictlan:~/www/experiments/gentle/` (`--dry-run` lists the changes). Otherwise, upload the contents of `dist/` to any static web host. No routing rewrites or server-side runtime are needed. The app works at either a domain root or a subdirectory. Serve JavaScript with its standard MIME type. For a local deployment preview:

```sh
python3 -m http.server 5173 --directory dist
```

The application, shared theme module and documentation are written into `dist/`, including `methods.html`, `about.html`, `METHODOLOGY.md` and `README.md`. The build checks that the displayed version in `src/app.js` matches `package.json`. Computation takes place in a browser worker. Workspaces are saved to local storage on that browser; use JSON exports to transfer or back them up.

## Features

- A persisted choice of path convention: right to left for left modules (the default, as in CSSS26) or left to right for right modules. Relations, typed presentations, signed representatives, operation formulas, surface tables and exports follow the choice without recomputing or changing class coordinates.
- Native MathML for mathematical displays, including paths, relations, representatives, operations, families, ring relations and surface data, with the bundled Latin Modern Math font. Coefficients 1 and −1 appear as an omitted factor and a minus sign.
- Thirty-two information cards attached to their headings, with source links and statements in the selected path convention. Help contains the manual and a grouped card index; its location control opens the corresponding view without computing. Open cards retain their state during a convention change, but their state is not stored.
- A 2400 × 1260 drawing area with an initial 800 × 420 view, Zoom in/out, Fit and Reset. Ctrl/Cmd + wheel and pinch zoom around the pointer; drag empty canvas with Select, or use the middle button, to pan. Keyboard moves stay ten drawing units at every zoom.
- Typed presentations via **Edit as text** in Algebra, with line-numbered errors, Apply/Cancel and a single undoable Apply. Surviving vertex labels retain their positions; new vertices are arranged automatically.
- **Copy link to this algebra**, in the tab toolbar and in Export, carries the presentation, field characteristic and degree bound. Opening a link adds a tab (up to 40) while existing tabs remain open; malformed or oversized links are rejected. The presentation is readable by anyone with the link; the fragment is removed after opening. Links are limited to 16 000 characters; use JSON for larger presentations.
- Mouse and touch quiver editor, loops, parallel arrows, movable vertices, editable labels, zero relations, undo/redo, and keyboard controls.
- System / Light / Dark theme choice (saved locally; System follows live device changes), seven examples (including the distinguishing pair in APS §9), JSON import/export and browser-local persistence.
- Multiple algebra tabs with separate fields, editing histories, computed reports and operation histories. New, duplicate, close and reopen controls; whole-session JSON export/import.
- Gentle-condition and finite-dimensionality validation.
- Exact rational arithmetic or prime-field arithmetic, including characteristic two.
- Hochschild cohomology and homology: dimensions and explicit quotient-basis representatives.

Displayed cochains use the notation `[a₁|…|aₙ] ↦ b`: the normalized tensor of inputs `a₁,…,aₙ` is sent to output `b`, and unlisted inputs map to zero. For example, `[ε|ε] ↦ e(1)` and `[ε|ε] ↦ ε` are different cochains because their outputs differ. Chains write the leading factor first, as `a₀[a₁|…|aₙ]`.
- Cup product, Gerstenhaber bracket, signed cap product, Connes operator, and a documented normalization of the Lie derivative on homogeneous linear combinations.
- Cyclic homology from the mixed-complex totalization; de Rham dimensions and Connes ranks.
- All-degree cohomology and homology families, full cohomology ring presentation, and formula queries through degree 100000.
- Bardzell-resolution group queries independently of the bar-complex range.
- Complete HH¹ bracket table, center, and derived series.
- Algebra dimension, global dimension, ℬ-maximal and Γ-maximal paths, complete circuits, spanning-forest complement, and path-count matrix.
- Combinatorial marked ribbon graph, boundary components, genus, winding data, and the AAG invariant.
- Standard surface diagrams in the APS page-23 layout, with symplectic α/β curves, boundary collars and punctures; separate diagrams for disconnected components, SVG downloads and horizontal scrolling on mobile.
- Complete derived invariant: connected-component surface and boundary/puncture data, genus-one gcd, higher-genus parity and Arf branches. Compare any two tabs over the same field, directly from their quivers without computing the bar complex.
- JSON session, quiver, results and derived-invariant exports carry the gentle version, ISO export timestamp and chosen convention. Stored quivers and representative data remain in travel order, with a separate `displayed` projection in the chosen convention. LaTeX reports state and use that convention. JSON imports accept stamped and older files.
- Standalone LaTeX report with the presentation, representatives, structural data, checks, and operation history. Compile with LuaLaTeX.
- Separate JSON and LaTeX exports of the derived invariant, cycle/intersection evidence, and comparison with both input presentations.

Text input uses one statement per line; `#` begins a comment:

```text
convention: left
name: A₃ with a zero relation
vertices: 1, 2, 3, 4 # 4 is isolated
α: 1 -> 2
β: 2 → 3
β α = 0
```

`name:` and `vertices:` are optional; arrow endpoints create their vertices. `convention: left` or `convention: right` declares the order of products independently of the current setting; without it the current setting applies. For the example above, `β·α = 0` and `β*α = 0` are also accepted. Under `convention: right` the same relation is `α β = 0`. Use distinct labels of at most 32 characters. Bare labels contain no spaces, colons, commas or `->`; JSON-quoted labels handle special characters (and are emitted automatically when needed). The drawing and text use the same mathematical validation and computation. The canvas relation tool always selects the first arrow travelled, then the next arrow. Cancel discards text edits; Escape also cancels. Drawing edits update the text while the text editor is closed.

The drawing uses the larger bounds consistently for pointer and keyboard edits, Arrange, JSON/session imports and typed presentations. Surviving typed labels retain their coordinates. Fit includes curved arrows and loops; Reset restores the initial view without moving vertices. Copy link records positions throughout the drawing area, subject to the 16 000-character link limit.

Choose **New tab** to draw another algebra or **Duplicate** to start from the current presentation. Loading an example replaces the current presentation (Undo recovers it); opening JSON adds tabs. Switching tabs cancels an unfinished calculation and retains completed reports and histories. Up to 40 tabs are supported. Quivers and field/degree settings survive reloads; reports and histories remain in memory during the session and should be exported before reloading. Previously saved single-quiver workspaces migrate automatically.

Open **Surface & derived invariant → Complete derived invariant**, compute the invariant or select another algebra tab and compare. For a useful check, load APS Λ₁ and Λ₂ into separate tabs: they have the same AAG invariant but gcd values 0 and 2, so they are not derived equivalent. A comparison becomes stale when either presentation or field changes. Changing only the degree bound retains a computed derived invariant and comparison. Undoing or redoing a name or layout edit leaves the calculus report current.

Results are organised into five tabs: **Overview**, **Groups**, **Operations**, **Structure** and **Surface & derived invariant**; the checks of a calculation are listed at the end of Overview. Buttons inside each panel select its view, and each algebra remembers its last view in each group during the session. Groups contains cohomology, homology and cyclic homology; Operations contains products and operators, HH¹ Lie algebra and the higher-degree Bardzell query; Structure contains the presentation and all-degree formulas/ring. Surface and the complete derived invariant need no calculus computation.

Result tabs support Left/Right/Home/End. With focus inside the quiver editor, V/N/A/R/D select tools, Delete removes the selected item, and Escape returns to Select. Choose Vertex, focus the canvas and press Enter or Space to add a vertex at the next free grid position; Tab to vertices/arrows and press Enter or Space to use the current tool. With Select, arrow keys move the focused vertex. Ctrl/Cmd Z remains available throughout the workspace. Algebra tabs support Left/Right/Home/End and Delete to close; the separate **Close tab** button closes the active algebra.

## Mathematical scope

Read [Methods & scope](docs/METHODOLOGY.md) before comparing numerical representatives with the paper. Path multiplication follows the selected convention. Reversal of the bar factors and the sign (−1)^{n(n−1)/2} transport degree-n representatives from the internal travel order to left-module notation; cyclic total complexes also use the summand sign described there. Bases in the operation panels are deterministic row-reduced bar bases, not the paper's named circuit bases. The full ring and all-degree family panels use the paper's generator descriptions instead.

Individual operations construct finite complexes. Current guardrails are 200 algebra basis paths, 900 vectors per complex space, 150000 enumeration steps, and degree 128. Formula queries do not construct these complexes. If the bar calculation hits a resource limit, the app falls back to exact circuit-based dimensions and labels the representatives as unavailable. Individual operation limits report an error; they never report a fabricated zero. These are complete calculations in the requested degrees when successful, not an unrestricted symbolic algebra system.

The marked surface has a combinatorial description and a standard schematic drawing; interactive curve drawing/unwinding is not implemented. There is no symbolic polynomial parser, non-prime-field coefficient extension, periodic/negative cyclic homology, or claim of independent mathematical certification. Periodic and negative cyclic homology are not the cyclic invariant computed in the paper. This is a new implementation requiring independent review before relying on it for a research result.

## Surface images

The Surface tab works directly from the quiver, independently of the calculus degree and path-basis limits. The diagrams follow APS p. 23: handles on the left, boundary components above on the right, punctures below, and no marked points. Genus-zero diagrams have a symmetric body with centered boundary and puncture arrangements. Green light/dark variants match the application theme. The αᵢ/βᵢ curves form a standard geometric symplectic basis of the capped surface; the computed winding data use a separate ribbon-cycle basis γⱼ. Dashed curve segments lie on the hidden sheet.

`assets/surfaces/` contains **1458 pre-generated SVGs** (light and dark variants of 729 surfaces), covering all triples with `0 ≤ g,b,p ≤ 8`. SVG keeps the diagrams sharp at any resolution and needs no image-generation service or browser rendering library. Images are served as ordinary static files. For larger triples, the app generates a lightweight SVG once and caches it during the session.

To extend the static range:

```sh
npm run surfaces -- --genus 12 --boundaries 12 --punctures 12
npm run build
```

The generator writes a manifest that the app reads automatically, so extending the range requires no source edits. `--output DIRECTORY` selects another destination; the application serves `assets/surfaces/`. A run is limited to 20000 themed images. Each component's **Download SVG** button exports a standalone, scalable image. The diagram viewport supports touch and keyboard horizontal scrolling.

## Validation and research use

This software has undergone AI-assisted, machine-checked validation including independent low-degree reference computations, differential testing, bounded exhaustive testing, metamorphic/property testing, and domain-specific mutation testing. These procedures provide substantial evidence of correctness but do not constitute a formal proof of correctness of the complete implementation.

Selected low-degree Hochschild homology computations can also be exported with exact certificates checked by an implementation-independent Python verifier. See [`validation/VALIDATION-REPORT.md`](validation/VALIDATION-REPORT.md) for measured bounds, counts, fields, degrees, mutation results, limitations, and reproduction commands.

## Verification

```sh
npm run verify        # about 60 s: unit tests, checks, the extended validation suite, the CSSS26 checks, build
npm run verify:full   # also every tests/browser*.mjs check against dist/ (needs chromium)
npm run bench         # timings and sizes near the resource limits; results in bench/results.json
npm run cards         # regenerate pre-rendered card and Help content from docs/cards/
```

`tools/verify.sh` runs, and stops at the first failure: `npm test`; `npm run check`; the validation regressions
and the certificate verifier; `validation/report.py --level extended --no-write` (the independent oracle for
dimensions, cup, cap and bracket, curated and bounded-exhaustive comparisons, property and mutation tests);
the checks of `validation/csss26/` against the published examples and conventions of CSSS26; and the build.
`python3 -m validation.report --level extended` regenerates `validation/VALIDATION-REPORT.md` for a release.

`npm run check` includes a stylesheet-token contrast check (4.5:1 for text and 3:1 for meaningful graphics in both themes), documentation generation/escaping checks, and shared theme state, focus and live-system-change checks with available or blocked storage. Tests compare known examples in several characteristics, the small and bar resolutions, circuit formulas, and the mixed complex. Operation tests cover characteristic-two products, nonzero brackets and caps, Connes coefficients, graded commutativity, skew symmetry, Jacobi, the bracket derivation identity, and Cartan compatibility in the documented convention.

Derived-invariant tests include the APS §9 pair, genus-zero examples, punctures, disconnected components, both higher-genus parity branches, and a genus-two pair with identical boundary data but different Arf invariants. Arf values are independently checked by Gauss sums. Three hundred deterministic generated presentations test relabeling and input-order invariance. Representative regressions check both characteristic-two classes in degrees 1–5 and both resolutions, plus the degree-zero cochain domain.

`tests/browser.mjs` exercises the actual UI through Chromium's DevTools protocol with no test dependency. Start the app on port 5173, start headless Chromium with remote debugging on port 9222, then run `node tests/browser.mjs`. The test profile should be disposable; the script edits its saved workspace.

`node tests/browser-derived.mjs` tests the new representative display, tab and worker isolation, comparison outcomes, stale comparisons, session persistence/import, LaTeX export and phone/tablet/desktop layout. It replaces the disposable profile's saved test session.

`node tests/browser-surface.mjs` checks ordinary and label-collision characteristic-two representatives, static surface assets, disconnected surfaces, a genus-ten fallback beyond the calculus path limit, and mobile scrolling. Use a disposable browser profile for this test as well.

`node tests/browser-presentation.mjs` checks typed input, line errors, Apply/Cancel, undo and preserved positions, both Copy link controls, linked settings and tabs, malformed/oversized links, the 40-tab limit, saved-session preservation, themes and responsive controls. It also replaces the disposable test workspace.

`node tests/browser-cards.mjs` checks card placement and path-convention updates, Help navigation, keyboard controls, both themes and the 390 px layout. It uses the same disposable browser setup.

`node tests/browser-mathml-canvas.mjs` checks native MathML values, zoom/pan/pinch, exact pointer and keyboard edits, expanded imports and typed positions, stamped downloads and themes at phone/tablet/desktop sizes. Use the same disposable Chromium setup.

## Files

- `src/linear.js`: exact field arithmetic and linear algebra.
- `src/engine.js`: complexes, quotient bases, operations and algebraic checks.
- `src/structure.js`: circuits, all-degree formulas, ring and ribbon data.
- `src/derived.js`: complete component invariants, cycle windings, intersection forms, symplectic reduction and derived-equivalence comparison.
- `src/surface-diagram.js`, `tools/generate-surfaces.mjs`: standard surface SVGs and static image generation.
- `src/worker.js`: computation isolation and independent formula checks.
- `src/app.js`, `src/style.css`: visual editor and responsive interface.
- `src/export.js`: escaped, standalone LaTeX generation.
- `src/convention.js`: the common path, representative and formula display transport.
- `src/mathml.js`: native MathML builders for the interface.
- `tools/tex-mathml.mjs`, `tools/generate-cards.mjs`: strict build-time conversion of approved card and Help content.

## Layout

- `src/`: the application; `assets/`: static images; `index.html`: the page.
- `tools/`: build, Markdown-to-HTML documentation, shared theme, contrast checking and image-generation scripts (`npm run build`, `npm run docs`, `npm run surfaces`).
- `tests/`: Node unit tests and browser checks.
- `validation/`: independent validation, differential and mutation testing.
- `docs/`: `METHODOLOGY.md`. The build publishes it at the site root, next to `README.md`, and generates HTML reading pages for both documents.
- Git-ignored: generated root `methods.html` and `about.html`, `dist/` (build output), `node_modules/`, `.cache/`, `.local/`, `.tools/`.
